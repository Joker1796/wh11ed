# CLAUDE.md — Faction pages

Directory-scoped doc for the per-faction rules/datasheet pages. The views live here
(`FactionRuleView.vue`, `FactionDatasheetView.vue`, `FactionDatasheetsView.vue`,
`FactionFaqView.vue`), but supporting composables/components are flat elsewhere — read this
file when touching those too: `src/composables/useFactionPage.js`, `useFactionChoice.js`,
`src/components/FactionPickerBar.vue`, `FactionDetachmentList.vue`, `FactionLayout.vue`
(the shared hero/tab-nav wrapper), `FactionsNavModal.vue` (mobile faction picker).

For the underlying faction data files (`src/data/factions/*.js`), their `sourceId`
sidecar (`src/data/sourceIds.json`), rule-granted keywords
(`src/data/conditionalKeywords.json`) and the SM-Chapter datasheet dedup mechanism — see root
`CLAUDE.md`'s Architecture section (those are build/data-pipeline mechanisms spanning
`scripts/*.mjs` too, not owned by this directory).

## Faction pages

`FactionRuleView.vue` (`/factions/:slug`, army rule + the active detachment's rule / stratagems / enhancements) and `FactionDatasheetView.vue` (`/factions/:slug/datasheets/:unit`, a `FactionUnitSheet`) both read faction data via `useFactionPage.js`. The **active detachment** and, for Space Marines, the chosen **Chapter** are one shared "army choice" held in `src/composables/useFactionChoice.js` — a **module singleton** persisted per faction slug to `localStorage['wh11ed-faction-choice']` (`{ slug: { det, chapter } }`; migrates the pre-chapter `wh11ed-faction-detachment` map once), so a pick on the rules page is reflected on the datasheets page and vice-versa. The UI is **`FactionPickerBar.vue`** — a bar sticky under the navbar (full-viewport-bleed background) that renders the Chapter and/or Detachment as compact "label + value + chevron" pill buttons, each an `AdaptivePicker` — a dropdown under the button from 901px up, `BaseModal` below — around `FactionDetachmentList.vue` (one option list for both, via its `tag` prop); it only renders when a faction has >1 detachment. Chapter↔detachment consistency (a chapter-locked detachment implies its chapter) lives in the bar, not the store.

**Another faction's detachments, after the faction's own** (2026-10-05, a Deathwatch player could
not find Gladius' rule or stratagems anywhere): a Chapter fields most of Codex: Space Marines'
detachments and Deathwatch Support, the Space Marines field Deathwatch Support. `useFactionPage`
appends them from `src/data/chapterDetachments.js` — generated by `gen-roster-data.mjs` with the
roster data, so the page offers exactly what the roster editor does, at the Chapter's own DP — and
reads their text from the other faction's file. Each carries `from`; `FactionDetachmentList` puts
a "<faction> detachments" heading over each such group. `src/data/chapterDetachments.test.js`
holds the page to the editor.

In `DatasheetCard`, bodyguard-unit names under a Character's **Leader/Support** ability are `RouterLink`s to those units' own datasheets (name→id via `FactionUnitSheet`'s `unitIndex`, always built from **EN** names); the group heading shows "Support" vs "Leader" (`dsSupport`/`dsLeader`) from the sheet's `core` field. **A printed/granted keyword is clickable** (`keywordLinksEnabled` prop, opt-in per caller — off by default) and emits `keyword-click`; `FactionUnitSheet` catches it and opens `KeywordUnitsModal.vue` listing every other unit in the SAME faction's roster carrying that keyword (`src/utils/keywordUnits.js`, checks both `keywords` and per-model `keywordsByModel`), each linking to its own datasheet page. The same modal also opens from a faction unit keyword named in rule prose, on any page (`useFactionKeywordUnits.js`, see `src/data/CLAUDE.md` → *Faction keywords in rule prose*). Faction keywords (ORKS, ADEPTUS ASTARTES…) are deliberately never clickable — virtually the whole roster shares those. `CombatPatrolFactionView` passes no `keyword-links-enabled` (units render inline on one page, not as separate routes, so there's nowhere for the modal's links to go — see `src/views/combat-patrol/CLAUDE.md`) — keywords there stay plain text.

**The weapon tables stay tables on every phone** (`DatasheetCard.vue`, mirrored in
`WeaponProfileModal.vue`). Six stat columns plus a name is a lot for a phone, and until
2026-08-27 the answer below 560px was to stack each weapon into its own labelled card — which
handed the whole width back to the name and turned three weapons into a screenful. A datasheet is
read mid-game, so height is the expensive axis. The columns are squeezed instead: smaller type,
cells padded to almost nothing, the name column given a share of the row and wrapping inside it,
and the ability tags moved onto their own line under the name. Nothing is hidden and nothing
scrolls sideways.

The stacked cards now take over only below a **300px** card — narrower than any phone (a 320px
phone gives the card 304px). That number is measured, not picked: `npm run weapon-table` renders
every sheet 1px above it and fails on a table wider than the card, a wrapped number, a word wider
than the name column, or a name over three lines (2026-10-04; it was ~380px, then 340px by eye).

**The way back from a unit page.** `/factions/:slug/datasheets/:unit` renders with `hero=false`
(no faction header, no in-page tabs) and the desktop keeps the same links in `.subnav` — which is
hidden ≤900px. So a phone had no way back to the faction's unit list at all: you left through the
drawer and walked in again through Factions → faction → Units. `FactionLayout` contributes a
back-to-units button to `MobileUtilityBar` for that page (`useContributeMobileActions(
'faction-back-to-units', …)`), offered at any scroll position rather than only once scrolled down,
and it calls `router.back()` when the list is where the page came from — the router restores the
saved scroll position on a real back, so the reader lands on the row they tapped instead of the top
of a ninety-unit list.

## A unit opens where the list is (2026-10-21)

**Where each part lives.** `FactionDatasheetsView` only puts the page together:
`FactionUnitChip` (a unit's chip, or a row on a wide screen), `FactionUnitMenu` (its "…" / right
click / long press menu and the "copied" toast), `FactionLegends` (the Legends prose, loading
itself; its heading is the list's, through `#head`), `UnitSearchField` (shared with the roster
catalogue), `useUnitPicks` (the modal, the column, compare, the session's last unit),
`useGroupFolds` (folded type groups) and `utils/datasheetGroups.js` (`groupByType`, `chapterOf`).
The rows a unit's "…" shares with its plate — pin, owned, copy name, share — are `UnitMarkActions`.

Tapping a unit in the faction's unit list used to leave for its page, and coming back lost the
reader's place in a ninety-unit list. The owner chose to change the move, not to remember the
place (2026-10-04/05, journal *Юнит в модалке и сравнение*):

- **The whole unit is `components/FactionUnitSheet.vue`** — the name plate with its actions
  (pin, owned, copy name, share, lore, image, the phone's "…"), the card and the keyword lists.
  `FactionDatasheetView` (the page) only loads the datasheets and sets the SEO name; the list
  draws the same component.
- **Up to 900px** (the app's picker threshold) the unit opens in a `BaseModal` over the list. The
  plate is the dialog's header (`#header` slot, `titleId` names the dialog) and the card scrolls
  under it (`contained` → `.modal-body`); the sheet carries its own faction colour, since the
  dialog is teleported out of `FactionLayout`. The list does not move, and Back closes the modal.
- **From 901px** the list is rows on the left and the unit sits in a sticky column on the right,
  scrolling inside itself (under `FactionPickerBar` where a faction has one). The plate's ◫ waits
  for a second pick; two units stand side by side, each with ✕, and a further tap in the list
  swaps the second. Differences are not highlighted (owner).
- **The address does not change** in either (owner). Share is one control on the plate / in "…":
  the system share sheet where `navigator.share` exists, the link copied otherwise.
- **Links to another unit of the faction change the unit in place** — a Leader's bodyguard on the
  card, a row of `KeywordUnitsModal` (`inPlace` → `pick`), a chip, a Legendary Proxy. One capture
  listener reads the link's href (`utils/unitLink.js`), so no link needs to know about it; a
  click asking for a new tab, another faction's unit and a button inside a link go their usual way.
- Everything else — search, a keyword popover elsewhere, links from other pages — still opens the
  unit's own page (owner).
- **A chip has a context menu** (owner, 2026-10-21): right click, or a long press on a phone —
  open, open in a new tab (in a browser tab only — the installed app has none), add to compare
  (desktop), pin, owned, copy name, share.
  `useLongPress` times the touch itself (iOS sends no `contextmenu`; chips take
  `-webkit-touch-callout: none`) and stops the click of the lift at the document: on a phone the
  menu's sheet rises under the finger and that click pressed its first row. The menu is the
  ordinary `ActionMenu`, opened at a point (`anchor`, through AdaptivePicker → PickerDropdown).
- **A chip carries "…" instead of the pin and collection marks** (owner, 2026-10-21), at every
  width: the same menu hung from the button, whose rows say both marks' state; the marks' key
  above the list went with them, and an owned unit shows the catalogue's `.owned-badge`. Under the
  name, the price at the left (Legends and owned beside it) and a Space Marines unit's Chapter at
  the right — wrapping to a line of its own only when it does not fit. On a phone the "…" holds the
  chip's top right corner; on a desktop row it stands at the end of the name's line.
- **Type groups fold** (owner, 2026-10-21): each heading is an accordion with the group's count,
  open by default; what is folded is kept per faction for the session, and a search opens every
  group so nothing it found is hidden.

## Legendary Proxies (2026-10-21)

A faction's Legends publication names retired units with no datasheet of their own and the Codex
sheet each is fielded as (`src/data/factionLegends.json`; Space Marines and each Chapter, Orks).

- **The table is behind a button over the list** (`FactionLegendsModal`, beside "Hide Legends"):
  under the list's last group, inside a column that scrolls by itself, nobody found it. A search
  still lists the rows it finds after the units (`FactionLegends`); `#legendary-proxies` (old
  changelog links) opens the dialog. Loading: `useFactionLegends`; rows: `LegendaryProxyList`.
- **Each retired unit has a page beside the units** — `/factions/orks/datasheets/ufthak-blackhawk`,
  the address made from the name (`utils/legendaryProxies.js`; `legendaryProxies.test.js` keeps every
  one apart from the faction's unit ids and from each other). `FactionUnitSheet` shows the sheet it
  is fielded as under the retired name, with one line saying so; no pin or collection mark (both
  belong to real units and sync with the account), no lore. Not in the list; reached from the
  table's names, the "Proxy" badge's dialog, Ctrl+K (a row of its own above the sheet's) and its
  own SEO page. A Chapter has its own pages, as its folded units do.
- **The "Proxy" badge is on a retired unit's page only** (owner, 2026-10-22 — not on the sheet it
  is fielded as): under "Legends" in the statline's spare space (`DatasheetCard`, `proxy` — its
  title, "Legendary Proxy → Warboss"); a tap opens that sheet's row of the table. `npm run
  legends-tag` measures a retired unit's page for every sheet one is fielded as.

## One route, three pages (2026-09-28)

`/factions/:slug`, `/datasheets` and `/faq` are children of one route whose component is
`FactionPagesView`: `FactionLayout` (hero, tabs, FABs) plus a `RouterView` of its own, fading the
child over (`fade`; a sideways slide by the tabs' order until 2026-09-29) with `pageLeaving` / `pageArrived`
from `usePageMotion` so the router sets the scroll in the gap. The three pages therefore draw NO
layout of their own — a plain root `div` each. The unit page `/datasheets/:unit` is a top-level
route (its own hero-less `FactionLayout`), a level deeper. Every faction route names a
`meta.prefetch` (router/prefetch.js) so the page arrives with its data. `router/factionRoutes.test.js`
pins the shape.
