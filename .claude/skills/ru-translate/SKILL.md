# RU-тексты

## Что НЕ переводится (жёсткая конвенция)

- **ALL-CAPS keywords** — `INFANTRY`, `VEHICLE`, `WARLORD`, `T'AU EMPIRE`. В русском тексте
  ставится голое английское слово: «модель CHARACTER», не «ТЕХНИКИ (VEHICLE)». Жирным не
  выделять — рендерер сам.
- **Названия юнитов, детачментов, стратагем, улучшений, миссий, твистов.** У них есть парная
  русская подпись (`nameRu`/`titleRu`), которая рендерится отдельной строкой — это и есть место
  для перевода названия, а не сам заголовок.
- **`[BRACKET]`-способности** — по ним ищется текст в `coreAbilities`.

Русскоязычный гайд сообщества (в приватном `wh-glossary`, если он склонирован рядом) покрывает
художественную прозу Black Library. Он **не отменяет** правило выше: оттуда берутся флейворы и
транслитерация, не термины правил.

## Транслитерация

Следовать апострофам источника, апостроф типографский `’` (U+2019): `Kauyon` → «кауйон»,
`Mont’ka` → «монт’ка», `T'au` → «т’ау». Латиница внутри русского текста сохраняет свой апостроф.

Решённые случаи записываются в `src/data/CLAUDE.md` → Bilingual content conventions — это
источник правды репозитория, он перекрывает глоссарий сообщества (например `Scion` → «сцион»,
а не «скион» и не «отпрыск»).

Приоритет написания: 1) уже существующий RU `flavor` в том же файле, 2) `wh-glossary`,
3) бесспорная транслитерация. Ничего не подошло — **пропустить и спросить**, а не выдумать:
у GW много намеренно исковерканных имён, наивная транслитерация даёт мусор.

Глоссарий грепать, **никогда не читать целиком** (3.8 МБ): `grep -iP '^Kauyon\t'
../wh-glossary/terms/*.tsv`. Исходный `.docx` не открывать вовсе.

## Глоссы

Предпочтительная форма — токен `[gloss:<id>:<видимая подпись>]`, определение один раз в
`src/data/glossary.js` (`{ term, en, ru }`). Токен ставится **в обе** локали и не влияет на
паритет блоков. Старая форма `**рус** (eng)` мигрируется по мере касания. Не глоссировать то,
у чего уже есть свой попап (ALL-CAPS keywords, `[BRACKET]`).

## Паритет — обязателен

Счётчики блочных маркеров (`▪ ◈ → ### ◆ [img:]`) в паре `en`/`ru` должны совпадать, `**`
сбалансированы, у каждого EN-поля есть RU-текст. Проверка:

```bash
npm run parity
```

## Тексты вооружения в конструкторе

`npm run roster:texts-ru` генерирует RU-строки вооружения из EN, в очередь перевода они **не
идут**. Fail-open: непонятую формулировку скрипт оставляет целиком английской — это норма, а не
пропущенная работа.

## Очередь перевода при бампе данных

`npm run translate:queue` собирает изменённое из `../wh40k-appdata/changes.json`. RU-проход
делается **отдельно** от EN — см. `DATA-SYNC.md` §4.
