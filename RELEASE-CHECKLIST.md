# Чек-лист проверки перед релизом

Автоматические гейты ловят данные и логику, но не ловят сценарии: «создал ростер со своими
лимитами → взял его в партию на двух телефонах». Этот файл — список таких сценариев. Каждый
кейс — **действие → что должно быть**. Если кейс однажды сломался у игрока, рядом стоит ссылка на
отчёт или версию, а сам кейс — кандидат в автотест.

## Как пользоваться

Три уровня, по нарастающей:

| Уровень | Когда | Сколько | Что |
|---|---|---|---|
| **A. Смоук** | каждый релиз | ~15 мин | раздел 0 + кейсы с пометкой **[A]** |
| **B. Зона** | релиз трогает зону | +15–40 мин | весь раздел затронутой зоны |
| **C. Полный** | крупный релиз, смена формата данных, бамп зависимостей | 2–3 ч | всё, плюс матрицы |

**Где проверять.** Минимум две поверхности на каждый кейс конструктора и трекера:
- телефон 375–393px (iPhone Safari и установленная PWA — это разные среды);
- десктоп ≥1200px («стол» конструктора — своя раскладка);
- промежуток 901–1199px — раз в уровень C (там нет ни стола, ни нижней навигации телефона).

**Язык и тема.** Смоук — в RU (основная аудитория) и в тёмной теме. EN и светлая — уровень C или
когда релиз трогает тексты/цвета.

**Тестовые ростеры.** Девять готовых ростеров описаны в `scripts/lib/test-rosters.mjs` — см.
раздел «Набор тестовых ростеров» в конце. `npm run test-rosters` печатает на них ссылки для стенда.

**Пометка [авто]** — кейс проверяет `npm run smoke` или тест в `npm test`; руками его смотреть не
нужно, пока автопроверка зелёная. Пометка стоит только там, где проверка **падает на сломанном** —
это проверено поломкой, а не предположено.

## Перед ручной проверкой — автогейты

Ручная проверка начинается только на зелёном:

```bash
npm test && npm run lint && npm run build
npm run roster:data:check && npm run modifiers:check
npm run dupes && npm run radii
npm run sync            # после правки данных — см. скил data-gates
npm run smoke           # по dist/: тестовые ростеры в Chrome, 390 и 1280px — каждый релиз
npm run smoke -- --wide # + все фракции (правила, FAQ, 4 датащита) — уровень C
npm run a11y            # по dist/, когда релиз трогает вёрстку или цвета
```

`npm run smoke` на **каждой** странице ловит ошибку JS, боковую прокрутку и сырую разметку правил
(`**…**`, `[gloss:…]`, `[core:…]` в видимом тексте), плюс отдельные проверки, отмеченные ниже
[авто]. Шум статического превью (нет API за ним, CORS локального стенда) отфильтрован.
`--shots=<папка>` сохраняет скриншоты для проверки глазами, `--only=<кусок пути>` сужает обход,
`--en` — английская версия.

Перед релизом, который трогает конструктор или импорт: прогнать корпус листов
(`python3 scripts/fetch-listhammer.py --all <файл>` и `npm run roster:imports -- <файл> --all`)
**до и после** правки и сравнить вывод — новые строки = новые находки.

## 3. Трекер партии

### 3.1 Матрица настройки партии

Каждая ячейка — «создать партию → пройти раунд → закончить». Уровень C — вся матрица; уровень B —
строки, которые трогает релиз.

| Режим | Ростеры | Устройства |
|---|---|---|
| Обычная | без ростеров | одно |
| Обычная | ростер у одной стороны | одно |
| Обычная | ростеры у обеих | две (синхронная) |
| Обычная | ростер со **своими** ограничениями | одно |
| Обычная | ростер **без лимита** | одно |
| Doubles 2×2 | у каждого участника свой | одно и четыре |
| Combat Patrol | — | одно |

- [ ] **[A]** Обычная партия без ростеров: мастер → старт → очки за первичку → конец → история.
- [ ] Ростер со своими ограничениями взят в партию: значок виден в выборе ростера. Размер битвы
      игрок выбирает в мастере сам — ростер его не задаёт (кнопки «играть этим листом» нет с
      2026-08-28). Если детачменты ростера дороже лимита размера битвы, трекер показывает DP красным
      («5 / 3 DP»), но начать партию не мешает.
- [ ] Ростер, который не подходит размеру битвы или фракции, виден, но недоступен с причиной.
- [ ] Архивные ростеры в выборе отсутствуют.
- [ ] Черновик настройки партии переживает перезагрузку.

### 3.2 Опции «что отслеживать»

## Набор тестовых ростеров

`scripts/lib/test-rosters.mjs` — спецификации, не сохранённый JSON: юниты по id, оружие по
подписи опции, поэтому набор переживает перегенерацию данных. `test-rosters.test.js` собирает
каждый и держит его назначение: законный ростер без ошибок, ростер с ошибками — ровно с теми, ради
которых собран. Переименованный юнит или опция роняет тест, а не тихо меняет ростер.

| Ключ | Ростер | Что проверяет |
|---|---|---|
| `leaders` | SM 2000, Assault Brethren: Captain + Ancient в Intercessors с Furious Assault, второй отряд контрольный | модификаторы лидера и апгрейдов |
| `havocs` | CSM 1000: Havocs с 4 heavy bolter и Power fist, контрольные Havocs | «одно из двух» |
| `breachers` | Imperial Agents 1000: Navy Breachers с заменами, контрольные | строки «на профиль» |
| `own-limits` | SM «Свой» 1500 / 2 DP / 2 улучшения / 2 копии / Battleline 4 | свои ограничения везде |
| `unlimited` | Orks «Без лимита», 3 детачмента, 33 юнита, ~3000 очков | снятие лимитов, большой ростер |
| `allies` | GSC Brood Brothers Auxilia + Cadian Shock Troops, Leman Russ | союзники |
| `legends` | CSM: Chaos Lord on Juggernaut | Legends |
| `archived` | SM в архиве | архив |
| `errors` | CSM Incursion: 3 детачмента, 4 копии Havocs, нет Mark of Chaos | плашка ошибок |

Не вошли (нужны отдельно, когда релиз трогает их зону): цепочка прикреплений (Huron → Masters
of the Maelstrom) — зависит от детачмента, проще собрать руками; облако и вход — нужен стенд API
(`npm run stand` в `wh11ed-api`).
