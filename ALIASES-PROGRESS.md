# RU search aliases for datasheets — progress tracker

> Прогресс-файл на случай, если сессия оборвётся на середине. Живёт на диске (не зависит от
> git-коммита), но раз это долгоживущая многосессионная работа — стоит коммитить по ходу дела,
> как `DATA-9NN-TODO.md`-хендофф в `two-machines-workflow`, не только в самом конце.

## Идея (контекст, зачем это вообще)

Поиск (Ctrl+K) ищет юнитов только по точному вхождению английского имени
(`src/composables/useSearch.js`'s `searchDatasheets`, индекс —
`src/data/datasheetIndex.js`, генератор — `scripts/gen-datasheet-index.mjs`). Русскоговорящему
пользователю не всегда очевидно английское написание, особенно у нарочно исковерканных имён
ксеносов (Ghazghkull, Vect, Yriel…), а у части юнитов есть устоявшиеся в сообществе прозвища
(Ghazghkull → «Газя», Abaddon → «Абба»/«Безруков»). Решение — скрытое поле алиасов, влияющее
только на поиск, никогда не отображаемое как «имя» юнита (имена юнитов остаются английскими —
это жёсткая конвенция, см. `CLAUDE.md` → Bilingual content conventions).

## Статус: механизм ЗАВЕРШЁН, ПРОВЕРЕН, ПЕРВАЯ ПАЧКА ДАННЫХ ВНЕДРЕНА

### Что сделано (код, не трогать без причины)

1. **`src/data/datasheets/ru/<slug>.js`** — новое опциональное поле `aliasesRu: string[]` на
   любой юнит в RU-оверлее (там же, где `flavor`/`abilities`/`loadout`). Для одного конкретного
   именного персонажа — см. таблицы выше, 32 юнита уже заполнены (2 первые пачки).
2. **`src/data/datasheetAliasRulesRu.js`** (новый файл) — алиасы по ПАТТЕРНУ EN-имени, для целого
   класса юнитов сразу (все Terminator-датащиты во всех фракциях → «термосы» и т.п.). 36 правил,
   см. таблицу выше. Каждое правило — `{ pattern: RegExp, aliasesRu: string[] }`.
3. **`scripts/gen-datasheet-index.mjs`** — читает и личные `aliasesRu` из RU-оверлея (через
   `loadAliases(slug)`), и правила из `datasheetAliasRulesRu.js` (через новый `aliasesFor(name,
   personal)` — сливает оба источника в один де-дуплицированный список), и кладёт третьим
   элементом в каждую запись юнита: `[unitId, unitName, aliasesRu | null]` (`null`, не пропуск —
   `JSON.stringify` не умеет опускать элемент массива). Для 5 SM-капитулов (Chapter dedup) личные
   алиасы шаренных юнитов, как и сами юниты, берутся из `ru/space-marines.js`. Печатает в консоль
   сколько юнитов реально получили алиасы (`N with aliasesRu`) — сейчас **267 из 1434**.
4. **`src/composables/useSearch.js`'s `searchDatasheets()`** — проверяет алиасы ТОЛЬКО когда
   собственное имя не совпало (`!nameHit && aliasesRu.find(...)`), и если совпадение пришло
   именно через алиас — кладёт его в `titleRu` (в RU-локали), чтобы `SearchModal.vue` показал
   мелкую подпись под результатом («Ghazghkull Thraka» / «Газя»), тот же паттерн, что уже
   используется для стратагем/детачментов. Совпадение по алиасу работает независимо от
   активной локали (та же кросс-языковая конвенция, что и у `searchFactionRules`), только показ
   подписи гейтится локалью.
5. **Регенерировать индекс после ЛЮБОЙ правки алиасов (личных или паттернов):**
   `node scripts/gen-datasheet-index.mjs` (пишет `src/data/datasheetIndex.js`).
6. **Тесты:** `src/composables/useSearch.test.js`, блок `describe('datasheet unit search')` —
   4 новых кейса (личный алиас находит юнит + показывает `titleRu`; собственное имя не
   показывает лишнюю подпись; кросс-языковой матчинг работает и в EN-локали; паттерн-алиас
   «термосы» находит юниты сразу нескольких фракций). `npm test` — **263/263 зелёных**.
   `npm run build` — чисто.
7. **НЕ проверено вживую в браузере** (в этой сессии нет доступного браузерного тулинга) —
   логика проверена юнит-тестами на реальном `search()` и отдельным Node-скриптом,
   симулирующим `searchDatasheets` (прогнал «термосы», «рина», «лендак», «газя», «тифон»,
   «царь», «крид», «врайты» — все находят правильные юниты), но перед тем как считать фичу
   полностью готовой к продакшену — стоит один раз открыть `npm run dev`, Ctrl+K, попробовать
   несколько запросов из таблиц выше и убедиться, что результат кликабелен и ведёт на
   правильную страницу.

## Как добавить алиасы дальше

**Персональный алиас (один конкретный юнит, обычно именной персонаж):**
1. Открыть `src/data/datasheets/ru/<slug>.js`, найти блок юнита по `id` (совпадает с EN-файлом
   `src/data/datasheets/<slug>.js`) — **сверить `id` заранее, GW иногда переименовывает
   персонажей между редакциями** (см. `⚠`-случаи Szarekh→the-silent-king,
   Ursarkar→Ursula Creed выше — «очевидное» имя не всегда совпадает с текущим датащитом).
2. Добавить `aliasesRu: [...]` первым полем в блоке, с комментарием
   `// Search-only aliases (see ALIASES-PROGRESS.md) — never displayed as the unit's name.`
   Если блока для юнита ещё нет в RU-оверлее — создать новый (см. любой пример выше).
3. `node scripts/gen-datasheet-index.mjs` — регенерировать индекс.

**Алиас на целый класс юнитов (прозвище применимо ко всем однотипным юнитам сразу):**
1. Добавить правило `{ pattern: /\bWord\b/i, aliasesRu: [...] }` в
   `src/data/datasheetAliasRulesRu.js`. **Сначала сверить реальное EN-имя датащита** (`grep
   '"name":' src/data/datasheets/*.js`) — GW-имена не всегда совпадают с ожиданием (напр. орочьи
   «Nobz», не «Nobs»; множественное число «Immortals»/«Obliterators», не ед. число) —
   не добавлять паттерн вслепую, он должен реально что-то матчить.
2. `node scripts/gen-datasheet-index.mjs`.

**В обоих случаях:**
`npm test && npm run build` — не обязательно после каждой правки, но обязательно перед тем как
считать пачку законченной.

## Правила отбора (чтобы не наплодить мусор)

- **Транслитерация** — по возможности бери уже существующую в RU-прозе того же файла
  (`flavor`, диалоги, `note`) — переводчик её уже выбирал осознанно. Если её там нет и
  добавляешь с нуля — это семантически «наш перевод», не «истина», и должно звучать
  естественно для русского уха, а не быть механической транслитерацией через скрипт (у GW
  много намеренно исковерканных имён — орочьих, тиранидских, — где наивная транслитерация
  даст мусор).
- **Прозвища/сленг** — только реально устоявшиеся в русскоязычном сообществе (форумы,
  стримы, паблики), не выдумывать самому. Если не уверен, что прозвище реально используется —
  **спросить пользователя**, не гадать и не добавлять «на всякий случай». Неверное прозвище
  хуже отсутствующего — оно засоряет результаты и подрывает доверие к поиску.
- **Не для каждого юнита.** Рядовые юниты с генеричными названиями (Boyz, Terminator Squad)
  почти никогда не нуждаются в алиасах — их либо ищут английским словом, либо не ищут вообще.
  Приоритет — Epic Heroes / именные персонажи с неочевидным написанием (см. порядок ниже).

## Когда закрывать эту задачу

Нет жёсткого критерия «все 30 фракций» — это открытая, постепенно пополняемая работа, а не
разовый спринт. Разумный признак «первая итерация закрыта»: у каждой фракции с явно культовыми
персонажами (почти все, кроме, может быть, самых нишевых) есть хотя бы один алиас. После этого
файл можно свернуть до короткой заметки в `CLAUDE.md`/памяти вместо отдельного трекера —
по аналогии с тем, как `AUDIT-PROGRESS.md` остался как архив после завершения своего аудита.
